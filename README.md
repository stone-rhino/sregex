Stone Rhino Regular Expression (sregex) is a high-performance C++ library for multi-pattern regular expression matching.
Unlike [hyperscan](https://github.com/intel/hyperscan), which does not support partial matching, and [PCRE2](https://github.com/PCRE2Project/pcre2), which is relatively inefficient for multi-pattern partial matching, sregex is designed to address this gap. In scenarios such as streaming data leak prevention and sensitive information filtering, multi-pattern streaming redaction is especially important. sregex provides high-performance multi-pattern partial matching and can be used alongside libraries such as hyperscan and PCRE2 to enable efficient multi-pattern regular expression matching in different scenarios. One [example](examples/streaming_redaction_with_dfa.cc) in this project demonstrates how to use sregex together with other libraries to achieve streaming multi-pattern redaction.

## Features

- High-performance multi-pattern regular expression matching and partial matching
- Works with hyperscan, PCRE2, and similar libraries to support streaming multi-pattern redaction
- Suitable for data leak prevention, sensitive information filtering, and related scenarios
- Provides a High-level Intermediate Representation (HIR) for regular expressions, allowing developers to build custom matching logic based on HIR

## Performance Comparison

The benchmark results are generated by the project's [benchmark program](benches/sregex_pcre2_benchmark.cc) and illustrate sregex's performance in multi-pattern regular expression matching and partial matching scenarios.
Below are selected benchmark results:

| Scenario | sregex(DFA) Time (ns) | PCRE2 Time (ns) | PCRE2(JIT) Time (ns) |
|---------|----------------------|-----------------|----------------------|
| Single-pattern - Full match (constant string) | 101 | 146 | **25.5** 🟢 |
| Single-pattern - Full match (email format) | 379 | 589 | **243** 🟢 |
| Single-pattern - Full match (URL format) | 77.6 | 366 | **79.3** 🟢 |
| Single-pattern - Full match (TOKEN format) | **4.64** 🟢 | 72.3 | 39.0 |
| Single-pattern - Full match (repeated string) | 6352 | 106478 | **5911** 🟢 |
| Single-pattern - Full match (log format) | **51.8** 🟢 | 273 | 94.4 |
| Single-pattern - Partial match (quantifier) | 34.8 🟢 | 226(soft)<br>87.6(hard) | 232(soft)<br>93.4(hard) |
| Single-pattern - Partial match (branch) | 40 🟢 | 467(soft)<br>398(hard) | 495(soft)<br>389(hard) |
| Single-pattern - Partial match (repeat) | 250 🟢 | 22300(soft)<br>2903(hard) | 23010(soft)<br>2930(hard) |
| Multi-pattern - Full match | 11.4 🟢 | 194(alternation)<br>486(per pattern) | 68.7(alternation)<br>197(per pattern) |
| Multi-pattern - Partial match | 97.9 🟢 | 13834(alternation-soft)<br>5560(alternation-hard)<br>2475(per pattern-soft)<br>2378(per pattern-hard) | 14256(alternation-soft)<br>5527(alternation-hard)<br>2717(per pattern-soft)<br>2370(per pattern-hard) |

The benchmark results show that sregex performs exceptionally well in multi-pattern regular expression matching and partial matching scenarios, especially for multi-pattern partial matching, where it is significantly faster than PCRE2, with performance improvements of up to tens of times. For single-pattern full matching, PCRE2 in JIT mode still has advantages in some scenarios, but sregex is not designed primarily for single-pattern full matching optimization. Instead, it focuses on high-performance multi-pattern partial matching.

## Quick Start

### Prerequisites

* CMake 3.14 or newer: https://cmake.org/download/
* vcpkg (installed via cmake): https://github.com/microsoft/vcpkg
* A compiler with C++23 support (GCC 13.1 or newer): https://gcc.gnu.org/
* JDK 21 or newer

```shell
apt install openjdk-21-jdk-headless
```

### Build

The project provides [CMake presets](CMakePresets.json) to simplify the build process. Developers can use different presets to build the library, benchmark programs, example programs, and debug builds.
If you need to specify a custom compiler path, copy `CMakeUserPresets.json.example` to `CMakeUserPresets.json` and modify the compiler paths there, for example:

```json
{
    "name": "my-release",
    "inherits": "release",
    "environment": {
    "CC": "/usr/local/bin/gcc",
    "CXX": "/usr/local/bin/g++",
    "LD_LIBRARY_PATH": "/usr/local/lib64"
    }
}
```

Then use the specified CMake preset:

```shell
cmake --preset=my-release --fresh
```

#### Build the Library

- Configure CMake

```shell
cmake --preset=my-release --fresh
```

- Build

```shell
cmake --build build
```

#### Build the Benchmark

- Configure CMake

```shell
cmake --preset=my-benches --fresh
```

- Build

```shell
cmake --build build/release
```

- Run the benchmark

```shell
./build/release/benches/sregex_pcre2_benchmark
```

#### Build the Debug Version (includes benchmarks, examples, and unit tests)

- Configure CMake

```shell
cmake --preset=my-debug --fresh
```

- Build

```shell
cmake --build build/debug
```

### Integrate into an Existing Project

- Install the sregex library

```shell
cmake --install build/release
```

After installation, the sregex library and headers can be used via the system include and library paths. You can also install sregex to a custom location by passing the `--prefix` option. For example, to install sregex to `/specified/path`:

```shell
cmake --install build/release --prefix=/specified/path
```

- Include the sregex headers in your project

```cpp
#include <sregex/sregex.h>
```

- Link against the sregex library

```cmake
# If sregex is installed in the system path
target_link_libraries(your_target_name PRIVATE sregex)
# If sregex is installed in a custom path
target_link_libraries(your_target_name PRIVATE /specified/path/lib/libsregex.a)
```

- Use sregex in your project

1. Create a `Sregex::Sregex` instance once and reuse it for different patterns

```cpp
static Sregex::Sregex sregex("pattern");
```

2. Use the Sregex instance for matching

```cpp
bool match = sregex.isPartialMatch("input string");
```

Please refer to the [example](examples/streaming_redaction_with_dfa.cc) for usage details.
